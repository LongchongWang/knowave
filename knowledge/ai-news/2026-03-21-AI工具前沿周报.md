## 💻 Claude Code

> 本周发布密集，v2.1.80 和 v2.1.81 带来了 `--bare` 脚本模式、`--channels` 消息推送、大量稳定性修复，以及显著的内存优化。

| 项目 | 内容 |
|------|------|
| 最新版本 | v2.1.81 |
| 本期区间 | v2.1.80 ~ v2.1.81 |
| 最新发布 | 2026-03-20 |
| 类型 | 功能更新 + 修复 |

**✨ 新特性**

- 🔥 新增 `--bare` 标志，专为脚本化 `-p` 调用设计：跳过 hooks、LSP、插件同步，仅需 API Key，适合 CI/CD 场景
- 🔥 新增 `--channels`（研究预览）：允许 MCP 服务器向会话推送消息，支持将工具审批提示转发到手机
- 🔥 新增 `rate_limits` 字段到状态栏脚本，可显示 Claude.ai 的 5 小时和 7 天用量百分比及重置时间
- 新增 `source: 'settings'` 插件市场来源，可在 settings.json 中内联声明插件
- 新增 `effort` 前置元数据支持，可在 skill 和 slash command 中覆盖模型推理强度
- Plan Mode 默认隐藏"清除上下文"选项（可通过 `"showClearContextOnPlanAccept": true` 恢复）

**🐛 修复 & 改进**

- 🔥 修复多个并发 Claude Code 会话在 OAuth token 刷新时反复要求重新认证的问题
- 🔥 修复 `--resume` 丢失并行工具调用结果，导致显示 `[Tool result missing]` 的问题
- 🔥 修复 `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` 未能抑制 structured-outputs beta 头，导致 Vertex/Bedrock 代理网关返回 400 错误
- 修复语音模式 WebSocket 连接被 Cloudflare 机器人检测拦截的问题
- 修复语音模式服务端静默断开 WebSocket 后音频无法恢复的问题
- 修复 Node.js 18 上的崩溃问题
- 修复后台 Agent 任务在轮询间隙完成时输出可能无限挂起的竞态条件
- 修复插件目录在会话中被删除时 hooks 阻塞提交的问题
- 修复恢复 worktree 会话时未自动切换回对应 worktree 的问题
- 大型仓库（25 万文件）启动内存减少约 80 MB
- MCP read/search 工具调用折叠为单行"Queried {server}"（可用 Ctrl+O 展开）
- `@` 文件自动补全在大型 git 仓库中响应速度提升
- 插件安装提示简化为单条 `/plugin install` 命令

| 项目 | 内容 |
|------|------|

| 最新发布 | 2026-03-14 |

- 修复 Android HttpURLConnection 内存泄漏（TalkModeVoiceResolver）
- 修复 Docker 构建上下文中 gateway token 泄漏的安全问题
- 修复 Ollama 原生推理模式下仅输出推理内容的显示问题
- 修复 Signal 频道 schema 缺少 groups 配置的问题

## 🐾 Clawith

> 本周发布 v1.7.1，重磅推出 ClawHub 技能市场，修复了 Feishu 用户身份架构问题，并全面重构了日志系统。

| 项目 | 内容 |
|------|------|
| 最新版本 | v1.7.1 |
| 本期区间 | v1.7.1 ~ v1.7.1 |
| 最新发布 | 2026-03-21 前后 |
| 类型 | 功能更新 + 修复 |

**✨ 新特性**

- 🔥 ClawHub 技能市场上线：可直接从 ClawHub（OpenClaw 技能注册表）浏览和安装技能，也支持从任意 GitHub URL 导入
- 🔥 技能租户隔离：导入的技能按公司范围隔离，避免跨租户污染
- ClawHub API Key 配置支持，可访问认证后的技能注册表
- 租户级 GitHub Token 配置，提升 API 速率限制
- 统一日志系统（loguru）+ trace ID 支持，LLM 请求 ID 追踪，便于调试

**🐛 修复 & 改进**

- 🔥 修复 Feishu 用户身份架构：将主标识从 `open_id`（不稳定）改为 `user_id`（跨 App 稳定），解决多 bot 场景下用户重复和会话碎片化问题
- 修复多位数通知角标显示拥挤的问题
- 修复 IME 输入法与 Enter 发送的冲突
- 修复 Agent 头像 emoji 首字符处理
- 修复侧边栏 Agent 排序（现按创建时间倒序）
- 修复 ClawHub 429 限流处理
- 修复 ClawHub Key 保存时意外清除 GitHub Token 的问题

**⚠️ 破坏性变更**

- 升级必须逐版本进行（如 v1.6.0 → v1.7.0 → v1.7.1），不支持跨版本跳升
- 新增数据库表 `tenant_settings`，由 Alembic 自动迁移；Feishu 用户需手动运行一次迁移脚本清理重复用户

## 💡 本期观察

> 本周三个工具都在向"更稳定、更可集成"方向演进：Claude Code 强化了脚本化和 CI/CD 能力，OpenClaw 修复了多 Agent 协作的关键 bug，Clawith 则打通了技能生态的分发链路。

**对研发同学的建议：**

- Claude Code 的 `--bare` 模式非常适合接入 CI/CD 流水线，无需 OAuth 认证，只需 API Key 即可运行，建议在自动化脚本中优先使用
- Clawith 升级到 v1.7.1 后，如果你们使用 Feishu 集成，务必运行官方提供的用户迁移脚本，避免历史重复用户数据影响后续使用
- OpenClaw 的跨 Agent 子 Agent 调度 bug 已修复，如果之前遇到多 Agent 协作时工作空间路径错误，可以升级到 2026.3.13 解决

**趋势 & 认知：**

- **技能/插件生态正在成为核心竞争力**：Clawith 推出 ClawHub 市场，Claude Code 持续完善插件机制，工具的可扩展性已成为差异化重点
- **多 Agent 协作稳定性是当前主要痛点**：OpenClaw 和 Claude Code 本周都有针对多 Agent/并发场景的关键修复，说明这一能力仍处于快速打磨阶段，生产环境使用需保持关注
