## 💻 Claude Code

> 本周密集发布，v2.1.129 ~ v2.1.136 共 6 个版本，重点围绕 MCP 稳定性、插件系统增强、多端体验修复展开，并新增多项企业级配置能力。

| 项目 | 内容 |
|------|------|
| 最新版本 | v2.1.136 |
| 本期区间 | v2.1.129 ~ v2.1.136 |
| 最新发布 | 2026-05-09 |
| 类型 | 功能更新 + 修复 |

**✨ 新特性**

- 🔥 新增 `settings.autoMode.hard_deny` 配置项，支持 auto mode 分类规则无条件拦截，不受用户意图或例外影响，企业安全管控更精细
- 🔥 新增 `--plugin-url <url>` 参数，可直接从 URL 加载插件 zip 包，无需本地安装
- 🔥 新增 `CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE` 环境变量，Homebrew/WinGet 安装下可后台自动升级并提示重启
- 🔥 Hooks 现在可通过 `effort.level` 字段和 `$CLAUDE_EFFORT` 环境变量获取当前 effort 级别，Bash 工具命令也可读取
- 新增 `CLAUDE_CODE_ENABLE_FEEDBACK_SURVEY_FOR_OTEL`，企业通过 OpenTelemetry 采集响应时可重新启用会话质量调查
- 新增 `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`，可关闭全屏交替渲染，保留终端原生滚动历史
- 新增 `CLAUDE_CODE_SESSION_ID` 环境变量注入 Bash 子进程，与 hooks 的 `session_id` 保持一致
- 新增 `worktree.baseRef` 设置（`fresh` | `head`），控制 `--worktree` 和 `EnterWorktree` 的分支基准
- `skillOverrides` 设置现已生效，支持 `off`/`user-invocable-only`/`name-only` 三种模式
- Ctrl+R 历史选择器恢复默认搜索所有项目的全部提示词（回退 2.1.124 的变更）

**🐛 修复 & 改进**

- 🔥 修复 MCP 服务器在 VS Code 扩展、JetBrains 插件和 Agent SDK 中执行 `/clear` 后静默消失的问题
- 🔥 修复 MCP OAuth 刷新令牌在多服务器并发刷新时丢失，用户不再需要每天重新认证
- 🔥 修复并行 session 在刷新令牌竞争后全部 401 失效的问题
- 修复 `--resume`/`--continue` 在项目路径含下划线时找不到 session 的问题
- 修复 plan mode 在存在匹配 `Edit(...)` 允许规则时未能阻止文件写入
- WSL2：当 xclip/wl-paste 无法读取图像数据时，现通过 PowerShell 回退支持从 Windows 剪贴板粘贴图片
- 修复外部 SIGINT（如 IDE 停止按钮）不触发优雅关闭的问题，终端模式现在会正确恢复
- 修复 `unbounded memory growth`（10GB+ RSS）：当 stdio MCP 服务器向 stdout 写入非协议数据时
- 修复 `/context` 将 ASCII 可视化网格输出到对话中，每次调用浪费约 1.6k tokens
- 修复 1 小时 prompt cache TTL 被静默降级为 5 分钟的问题
- 修复 subagents 无法通过 Skill 工具发现项目、用户或插件 skills 的问题
- 修复鼠标滚轮在 Cursor 和 VS Code 1.92-1.104 中滚动过快的问题（上游 xterm.js bug）
- 修复 JetBrains IDE 2025.2 终端中滚轮处理异常（方向错误、加速失控）

**⚠️ 破坏性变更**

- `worktree.baseRef` 默认值为 `fresh`，这将 `EnterWorktree` 的基准改回 `origin/<default>`（2.1.128 起曾是本地 HEAD）；如需保留未推送提交，需显式设置 `worktree.baseRef: "head"`
- Gateway `/v1/models` 发现功能改为通过 `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` 显式开启（2.1.126-2.1.128 中为自动开启）

## 🦀 OpenClaw

> 本周连发 v2026.5.3 ~ v2026.5.7 共 5 个版本（含同日热修复），重点新增文件传输插件、统一流式进度草稿、Google Meet 语音桥接，并修复大量跨平台 bug。

| 项目 | 内容 |
|------|------|
| 最新版本 | v2026.5.7 |
| 本期区间 | v2026.5.3 ~ v2026.5.7 |
| 最新发布 | 2026-05-07 |
| 类型 | 功能更新 + 修复 |

**✨ 新特性**

- 🔥 新增**文件传输插件**，提供 `file_fetch`、`dir_list`、`dir_fetch`、`file_write` 四个 agent 工具，支持节点间二进制文件操作，单次传输上限 16MB，默认拒绝符号链接遍历
- 🔥 **统一流式进度草稿**：新增 `streaming.mode: "progress"` 配置，在 Discord、Telegram、Slack、Matrix、Microsoft Teams 上行为完全一致，告别各渠道各自为政的配置方式
- 🔥 **Google Meet + Twilio 语音桥接**：Meet 语音 agent 现在接入 Realtime Gemini 语音桥，支持分步音频流、背压感知缓冲和打断队列清除，响应更流畅
- **Gateway 启动性能优化**：插件、运行时发现、cron、schema、session、模型元数据均改为懒加载，大型安装启动时间和内存峰值显著降低
- Control UI 新增可折叠的 New Job 侧边栏，节省 cron 任务列表的屏幕空间
- OpenRouter 用户：新增通过 `X-OpenRouter-Cache` 头的可选响应缓存，扩展应用归因类别

**🐛 修复 & 改进**

- 修复 xAI/Grok 模型收到 OpenAI 风格 reasoning effort 控制导致 `Invalid reasoning effort` 错误
- 修复 LINE 渠道 `dmPolicy: "open"` 无通配符 `allowFrom` 时静默失败，现在提前报错
- 修复 iOS 配对：手动 `ws://` 连接私有 LAN 和 `.local` 网关现在可用，同时 Tailscale 和公网路由保持 `wss://`
- Docker 安全加固：`docker-compose.yml` 现在移除 `NET_RAW` 和 `NET_ADMIN` 能力并启用 `no-new-privileges`
- 修复 Discord 心跳 ACK 超时从网关启动时计算（应从实际心跳发送时计算），消除误重连循环
- 修复 Telegram/Codex 进度草稿中仅含工具输出时重复渲染条目的问题

**⚠️ 破坏性变更**

- v2026.5.5 的 `doctor --fix` 会将 `openai-codex/*` 路由重写为 `openai/*`，影响使用 OAuth 路由的 GPT-5.5 用户；v2026.5.6 已回退该修复，受影响用户需运行 `openclaw models set openai-codex/gpt-5.5` 恢复
- Docker 用户需拉取更新后的 `docker-compose.yml` 并重建容器，安全能力限制不会自动应用到已有容器

## 💡 本期观察

> Claude Code 和 OpenClaw 本周均保持高频发布节奏（分别 6 个和 5 个版本），两者都在重点强化 MCP 生态稳定性和企业级配置能力；GitHub 热榜则显示 CLI Coding Agent 赛道正在快速分化，opencode 的异军突起值得持续关注。

**对研发同学的建议：**

- 如果你在用 Claude Code 并遇到 MCP 服务器频繁断连或需要每日重新认证，立即升级到 v2.1.136，本次修复了 MCP OAuth 并发刷新丢失令牌的高频问题
- 关注 `anomalyco/opencode` 项目，其 28 天增速已超过 Claude Code，可以试用对比，了解其在哪些场景下体验更优
- MCP 工具选型建议优先考虑 `upstash/context7`（实时文档注入）和 `github/github-mcp-server`（代码库操作），这两个是当前增速最快、场景最明确的 MCP 服务器

**趋势 & 认知：**

- "AI Coding Agent 工具化"正在加速：从 IDE 插件到 CLI Agent，再到可编排的 subagent 体系，工具链正在向"可组合、可自动化"方向演进，Claude Code 的 hooks/skills/worktree 体系和 OpenClaw 的插件治理都是这一趋势的体现
- MCP 已从"概念"变成"基础设施"：context7、github-mcp-server 等工具的高速增长说明，MCP 不再是实验性协议，而是正在成为 AI Agent 工具链的标准接口层，值得在团队内推广使用
